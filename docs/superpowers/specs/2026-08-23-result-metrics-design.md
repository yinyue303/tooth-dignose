# 分类结果指标写入设计

## 目标

修改 `models/zero-shoot-classification.py`，使结果文件既保留每条样本的 `id`、真实标签和预测标签，也在文件末尾保存本次完整评估的 Accuracy、Precision、Recall 和 F1。

## 文件格式

脚本继续用制表符写入预测明细。全部预测完成并计算指标后，在同一个文件末尾追加一个空行和以下两列表格：

```text
metric\tvalue
Accuracy\t0.666667
Precision\t0.722222
Recall\t0.666667
F1\t0.655556
```

指标统一保留 6 位小数，并且每项只写一次。

## 数据流

1. 现有批量推理逻辑持续写入预测明细，保持运行中间结果可恢复。
2. 全部推理完成后，对去除首尾空白的预测标签计算四项指标。
3. 终端输出与文件写入使用同一组指标值，避免两处重复计算产生差异。
4. 以追加模式把指标表写到当前 `result_file` 的末尾，不改动已有预测行。

## 异常与边界

- Precision、Recall 和 F1 继续使用宏平均和 `zero_division=0`，与现有终端指标定义一致。
- 指标只在全部预测完成后写入，因此推理中断时文件仍只包含已完成的预测明细，不会出现不完整的最终指标。
- 不在每条预测行中重复存储全局指标。

## 验证

增加一个不加载大模型的轻量测试，使用固定标签验证输出文件包含原预测表和唯一的指标区块，并核对四项指标值及 6 位小数格式。
